Sort Blocks in Order

Procedural adherence6 branches108 test episodes
Same initial state, different instructions (scene 0, expert demonstrations).
InstructionSort the blocks in this order: red|green|blue, then …, then ….
DescriptionThree colored blocks have to be placed into the bins of matching color. Every branch ends in the same final arrangement; only the requested placement order differs, and it is read from the recorded placement events.
Variables
  • Order: all 6 permutations of red, green, blue
  • Arm: not specified by the instruction
Branches6 per scene, all from the same initial scene and robot state
CategoryProcedural adherence
PlatformSimulation · RoboTwin 2.0
Data318 train / 108 val / 108 test episodes · 89 eligible of 100 candidate scenes
ExpertMulti-branch expert, 5 refinement iterations · 89.0% scene eligible rate
Action budget1,000 actions
UsageTrain & Eval (test_clear) / Random Eval (test_random)

Fidelity checker

Checkers score simulator states and execution records (trajectories, contacts, activation events). Policies never see their output. Episodes run for the fixed action budget, followed by 250 passive physics steps, and are scored with no early stop on success.

Task success (TR)All blocks in matching bins and on the table; both grippers open; final configuration stable.
Joint success (JR)TR, plus: Measured placement order equals the requested color permutation.

Criteria as stated in the paper (Appendix, Table “Canonical instructions and episode-level success criteria”).

CheckGroupCondition
blocks_in_matching_binsTREach block lies in the bin of its color (x–y error ≤ 1.5 cm).
blocks_on_tableTREvery block rests at table height (z error ≤ 1.2 cm).
both_grippers_openTRBoth grippers are open.
sort_stableTRThe final configuration is at rest (≤ 3 mm motion and small rotation over the settle window).
requested_sort_orderJRRecorded placement events place one block at a time, and the observed color order equals the requested order.

The benchmark checker computes TR as all 4 TR checks, and JR as TR plus all 1 JR checks. Check names and grouping follow the frozen evaluation protocol roboinf.paper_table.origin_archive.v2.
