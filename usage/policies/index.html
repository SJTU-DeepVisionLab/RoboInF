Policy Interfaces

Connect π0.5, OpenWAM, GR00T or LingBot-VA through their upstream inference servers.

SJTU-DeepVisionLab/RoboInFv1.0.0

Run the checkpoint in its upstream inference server and install the matching client in the environment that runs RoboInF. Each adapter receives only the instruction, the current camera images and the robot state; the server is responsible for checkpoint-specific preprocessing, normalization and inference. Importing the benchmark itself does not require any of these clients.

Configuration file

The --config file is a JSON object with the address at which you started the upstream server. Unknown fields are rejected.

The OpenWAM and LingBot-VA clients import code under benchmarks/ and evaluation/ respectively: put the corresponding upstream repository root on the client Python path. Use one active rollout per server, and configure the sampling seed in the model service if it is supported — these remote calls do not promise a per-episode RNG reset.

π0.5 (pi_05)

Serve a checkpoint with OpenPI's ALOHA input transform. The adapter sends CHW RGB images as cam_high, cam_left_wrist and cam_right_wrist, the 14-value joint state and the original prompt. The server must return actions shaped [50,14] after its output transform; the runner executes the permitted prefix of the chunk. Deployments returning padded or delta actions need the matching OpenPI output transform.

OpenWAM (openwam)

Match action_mode to the checkpoint. The upstream client sends one action per request and manages its own action queue. For end-effector models, both proprioception and returned actions use the upstream rotation conversion. The default "eef_layout":"physical" converts simulator wxyz quaternions into the client's xyzw order and back. Choose "legacy_wxyz_values_as_xyzw" only for checkpoints trained by treating the original wxyz component values as xyzw.

GR00T (gr00t)

Use the N1.7-style native policy API with a compatible bimanual modality configuration:

  • camera keys front, left_wrist, right_wrist (the first is the benchmark's head camera);
  • state/action groups left_arm and right_arm, each six joints plus gripper;
  • language key annotation.human.task_description.

Images are batched as [1,1,H,W,3] and state as [1,1,7]. The server must return decoded absolute targets shaped [1,horizon,7] per group. A different embodiment requires a compatible server-side modality configuration.

LingBot-VA (lingbot-va)

Use the upstream RoboTwin checkpoint. The adapter requests native action blocks, skips the initial conditioning frame, composes relative poses with the measured episode-start pose, and supplies one absolute action per call. To match the checkpoint's relative-pose encoding it composes the stored four components exactly as the upstream RoboTwin client does (SciPy xyzw multiplication on the stored values). When a block has finished, quarter-frame RGB observations and that block update the model's KV cache. This interface expects the 16-channel RoboTwin output, not a 30-channel joint checkpoint.

The adapter tests use synthetic observations and deterministic replies to check camera layout, channel grouping, quaternion ordering and cache timing. They do not run the four checkpoints or reproduce leaderboard scores.
