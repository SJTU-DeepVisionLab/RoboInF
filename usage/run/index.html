Run a Policy

Set up RoboTwin and roll out a policy on the RoboInF cases.

SJTU-DeepVisionLab/RoboInFv1.0.0

Set up RoboTwin

Install RoboTwin following the RoboTwin installation and asset instructions, in the same environment that runs the benchmark, together with the simulator and the CuRobo planner. Obtain the assets separately under the terms of their providers.

Tested setupRoboTwin revision 266f3aa · MPLib 0.2.1 · NumPy 1.26.4 · Python 3.10
Expected layoutRoboTwin 2 source tree with envs/_base_task.py, env_cfg/task_config/demo_clean.yml, the Aloha-AgileX embodiment and its expanded planner configuration
EnvironmentUse a clean environment. On Linux, set PYTHONNOUSERSITE=1 so that a user-installed NumPy 2 does not shadow the version expected by MPLib's native extension.

Run a policy

Start the policy's inference server and install its client (see Policy Interfaces). For a local OpenPI server on port 8000, write {"host":"localhost","port":8000} to pi05.json and run a one-case installation check:

roboinf run --robotwin ./RoboTwin --data ./RoboInF-4K --domain val \
  --policy pi_05 --config pi05.json --limit 1 --output trial.jsonl

Remove --limit to evaluate every case in the domain. Supply a new output file for each policy and domain.

OptionDescription
--dataRoot of the downloaded RoboInF-4K dataset (required)
--domainval, test or test_random (required)
--robotwinPath to the RoboTwin source tree (required)
--policypi_05, openwam, gr00t or lingbot-va (required)
--configPolicy configuration as a JSON object (required)
--outputNew output JSONL file; an existing file is never overwritten (required)
--policy-seedFixed policy RNG seed, independent of the scene seed (default 0)
--taskEvaluate only one task, e.g. open_laptop
--limitEvaluate only the first n cases, for installation checks

Completed episodes are written to a temporary .partial file until the run finishes. An error leaves the partial output for diagnosis and does not assign a failure judgment. The benchmark does not install weights or a model service.

Observations

At step zero the policy is reset with the case instruction and its seed. At every query it observes:

  • three current RGB images: head, left wrist and right wrist (the front camera in the training data is not a policy input);
  • 14 joint/gripper coordinates, and 16 absolute end-effector/gripper coordinates when available;
  • the action index and simulation time.

Action spaces

Action specLayout
joint14_absoluteLeft six joint angles in radians and left gripper, then the same for the right arm.
eef16_absolute_wxyzFor each arm (left first): position in metres, unit quaternion in wxyz order and gripper, in the native RoboTwin arm-pose frame.

Execution and budgets

The runner executes at most 20 actions from each predicted chunk (fewer if the chunk or the remaining budget is shorter), discards the unexecuted suffix and obtains a fresh observation. It never stops early on task success. After the last action the simulator advances 250 passive physics steps before the fixed endpoint. The action budget is the smaller of the task budget and the initialized simulator limit.
